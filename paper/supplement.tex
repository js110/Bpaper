\section{Comparator Adaptations and Validation}
For the pointwise-maximal-leakage comparator, let \(l_i=\Pr(Y=1\mid X=i)\) and \(m=\sum_i b_i l_i\), with \(0\le l_i\le\alpha\mathbf{1}\{i\in S\}\). The task-channel specialization maximizes report probability subject to the published pointwise leakage constraints \(l_i\le e^\epsilon m\) and \(1-l_i\le e^\epsilon(1-m)\) for every state with positive prior mass~\cite{pml2024}. Randomized instances are checked against a general linear program. This is a task-channel specialization rather than a reproduction of every component of the original application.

PRIVIC learns a noisy location channel through Blahut--Arimoto and incremental Bayesian updates~\cite{privic2024}. Our BA/IBU/GIBU updates are checked against the authors' public implementation. The task adapter emits a truthful report only when the true state is eligible and the sampled location-channel outcome satisfies the task predicate. Because the adapter changes the output semantics, PRIVIC-T does not inherit the original geo-indistinguishability guarantee. Offline fitting is excluded from online gate timing.

The Bayesian-privacy comparator constrains each positive-probability output by \(D_{\mathrm{KL}}(b^y\|b)\le\kappa\)~\cite{bayesian}. The successful-report divergence is determined by task support, while the silence bound is solved by bisection. It is used as a per-output diagnostic rather than as a cumulative session guarantee.

\section{Robustness Boundary and Additional Stress Tests}
\subsection{Finite-Model Boundary}
The hand-grid ambiguity set uses \(v\in\{0.05,0.3,0.8\}\) and \(\alpha\in\{0.3,0.648,0.9\}\). Twenty new synthetic seeds, four users per seed, and 48 slots yield 80 trajectories per reported row at a fixed operating point. When the informed attacker's exact generating model is contained in the set, R-BSP records no local-cap violation in the reported in-set conditions, as expected from the finite-set construction, while retaining about 39.7\% of externally completable normal-task opportunities.

\subsection{Grid, Process, and Probe Sensitivity}
The original synthetic sensitivity study includes $4\times4$ and $16\times16$ grids in addition to the $8\times8$ main setting. For BSP at $\rho=0.1$, the corresponding MAP-cell hit rates are 7.54\% and 2.57\%, with simulated opportunity retention 10.85\% and 81.03\%, respectively. Because changing grid resolution also changes cell size, prior granularity, and the task-region library, these figures characterize resolution sensitivity rather than physical localization accuracy.

Grid resolution changes the representation itself; the next stresses instead perturb the process assumptions while keeping the nominal client model fixed. The post-review configuration deliberately violates two baseline assumptions. In the spatial-availability stress, the true and attacker availability probability is $0.35$ on one half of the grid and $0.85$ on the other, while the client continues to use scalar $\alpha=0.648$. In the nonstationary-mobility stress, the true and attacker movement probability alternates between $0.05$ and $0.8$ every eight slots while the client uses stationary $0.3$. A separate all-probe condition compares one-step mutual-information greedy selection with a two-step beam look-ahead. The latter is a deeper planning heuristic, not an optimal long-horizon adversary.

The main manuscript reports the key stress-test values in prose; the complete quantitative summary is retained here to avoid duplicating the same table in both documents.

The two-step probe heuristic does not dominate one-step greedy in the tested mismatch, so these experiments do not identify a worst-case task-planning adversary.

\section{Data-Driven Ambiguity-Set Construction}
The hand-grid stresses clarify the guarantee boundary but do not provide a data-grounded way to choose the ambiguity set. For the GeoLife replay, we therefore construct the ambiguity set without using the \GeoTestN{} isolated test windows. The \GeoDevN{} development windows define a coarsened reflecting-walk likelihood
\[
\Pr(\mathrm{change}\mid i)=v d_i/4,
\]
where \(d_i\) is the number of in-grid neighbors. Only change versus no-change events enter this likelihood; destination direction and jump distance are not fitted. Two thousand development state-path-group bootstrap replicates generate mobility candidates, and 2,000 validation state-path-group bootstrap replicates select the smallest set covering at least 95\% of predictive-likelihood winners.

The validation winner distribution is concentrated on two development-only smoothed population-prior candidates, with selection frequencies 84.15\% and 12.80\%. Retaining these two models gives 96.95\% cumulative validation selection mass, above the prespecified 95\% target. The development MLE is \GeoDevMLE{} with a 95\% bootstrap interval \GeoDevCILow--\GeoDevCIHigh{}; the validation point estimate is \GeoValMLE{}. Availability remains externally specified because GeoLife contains trajectories rather than task-delivery, willingness, deadline, or production-service observations.

A validation-best single-model BSP control is retained to separate improved model fit from finite-set robustness. The strict data-driven R-BSP and the disclosure-floor-aware RDF-BSP service frontier are reported in the main manuscript rather than duplicated here.

\section{Reproducibility and Provenance}
To make the preceding analyses auditable rather than merely repeatable in principle, the repository stores deterministic preprocessing, split metadata, configuration files, seeds, trajectory-level summaries, bootstrap outputs, provenance records, analysis code, and manuscript sources. The effective GeoLife analysis split contains \GeoDevN{} development, \GeoValN{} validation, and \GeoTestN{} test windows after model-input-group isolation. User IDs and complete 48-slot discrete state-path fingerprints are disjoint across the effective splits.

GeoLife point estimates average effective user windows and their constituent positions, whereas uncertainty intervals resample complete state-path groups so that duplicate model-input paths are not treated as independent clusters. The current automated suite contains 35 tests covering nominal, robust, and disclosure-floor posterior branches; gate reductions and maximality; informed-attacker integration; transition conservation; clustered-estimator weighting; GeoLife split and missing-minute handling; numerical replay; PML linear-program checks; PRIVIC author-code checks; and policy-envelope optimization.

The data-driven replay and post-review stress analyses are reported as exploratory; they are not treated as independent confirmatory superiority tests. The legacy \texttt{reset\_every} sensitivity rows were generated before the client/attacker reset-prior implementation was separated. Those conditions use no distinct client or attacker prior and therefore start from the same default uniform prior. A post-fix rerun of all nine reset conditions (360 trajectory rows) is stored in \texttt{results/reset\_sensitivity\_postfix}; its source-bound comparison record reports identical keys and zero numerical differences across the retained risk, calibration, completion, and utility metrics. Distinct-prior reset semantics are additionally covered by a regression test. No mobile-device energy measurement, production MCS task-log study, or independent external reproduction is claimed. The original Microsoft GeoLife archive and third-party article full texts are not redistributed in the submission package.
