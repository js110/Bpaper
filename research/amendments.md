# 方案修订与证据边界

1. Pilot 的固定正常/探测任务时隙与周期限频相位相关，导致不公平比较。正式实验前改为独立随机日程，各方法共享正常任务与外生变量。Pilot 不用于论文结果。
2. KL 分支基线在主实验后增加，为文献启发的探索性扩展。四个 κ 全部报告，不从测试集挑一个最优值。上次中断日志保留；完整新运行替代中断运行参与分析。
3. 匹配效用为观测曲线内插值，非单独部署并验证的精确匹配策略；CI 仅在中心曲线重叠且 >=95% bootstrap 重抽样有重叠时输出。无重叠不外推。静止/GeoLife 与随机参与的差异明确，随机游走/规律移动区间跨零。
4. 敏感性实验最初由防御与攻击共用错误模型。2026-09-15 增加 informed 条件，让攻击者使用实际生成概率而客户端使用错误概率；攻击者知道公开 gate 但不接收真实状态。12 条件、480 条轨迹，单独标为探索性。结果证明客户端 cap 不能保护拥有更准确模型的攻击者。
5. 实验中的 deadline 是固定时隙末批量释放；on_time 改变在截止前完成的概率。没有手机网络队列和可变时窗内连续采集过程，因此不称真实时延实验。报告延迟恒为 1 槽是设计结果，不是实测系统优化。
6. GeoLife 使用粗网格单用户 48 分钟样本，选择偏差、轨迹缺失和移动模型错误均可能影响外推。没有多用户协调任务分配、整体平台容量、激励均衡、不同空间粒度下同一米制位置命中目标或位置相关在线概率建模。
7. 正式计时是本机 Python 函数耗时，且 KL 与早期方法分批运行。不能把差异说成实现无关或移动设备上优势。无密码学实现，也无密码学性能数字。
8. 2026-09-18 内部审稿后增加描述性诊断：开发众数先验、粗粒度静止窗口、任务面积分层和 pooled raw completion；区域分组与新增 bootstrap 属于审稿后分析，不是原始预注册内容。脚本、输入哈希及逐条回应见 revisions/review1/ 和 results/review1_diagnostics/。
9. 更正“测试集不用于参数选择”的笼统表述：训练用户隔离仍成立，但近期 gamma 扩展和下凸包选择使用测试结果。现有区间是探索性、固定训练条件下的逐点区间。没有重训或新增模拟，不把这些文字修正计成新实验条件。
